Supabase

Banco de dados e sistema de login. Guarda imóveis, usuários, fotos e vídeos, com regras de segurança (RLS) que impedem qualquer pessoa de ver ou editar dados que não são dela.

O que acontece nos bastidores

1. Formulário de contato / leads

Um visitante envia uma mensagem sobre um imóvel → o Supabase salva o lead → automaticamente avisa o n8n → o n8n notifica a equipe (e-mail ou WhatsApp) na hora, sem ninguém precisar ficar checando o painel.

2. Alerta de novo imóvel (busca salva)

Um usuário cadastrado salva uma busca (ex.: "casas até R$ 800 mil no Boqueirão") → quando o administrador cadastra um imóvel novo que combina com essa busca, o n8n envia um e-mail automático avisando o usuário.

Sobre os rumores de vazamento

Como isso é evitado aqui

A maioria dos vazamentos associados ao Supabase não é uma falha da ferramenta em si — é uma tabela sem RLS ativado, ou uma chave secreta publicada por engano num repositório público. Este projeto evita os dois erros por padrão.

01

Senhas nunca ficam visíveis

O Supabase Auth guarda cada senha como hash — nem a imobiliária, nem um eventual invasor, conseguem ler a senha original.

02

Row Level Security em toda tabela

Cada usuário só vê e edita os próprios dados; só uma conta marcada como administrador cadastra ou edita imóveis — essa regra vive dentro do banco, não só na tela.

03

Chaves secretas fora do site

A chave "service role" do Supabase nunca aparece no código do site publicado — fica só em variáveis de ambiente privadas.

04

Webhooks do n8n com segredo

Cada URL de webhook do n8n inclui um token único difícil de adivinhar, e o n8n valida a origem antes de processar qualquer chamada.

05

HTTPS sempre ativo

Netlify fornece certificado HTTPS automático — toda a comunicação entre o visitante e o site é criptografada.
