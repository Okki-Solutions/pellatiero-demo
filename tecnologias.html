O que cada tecnologia faz

Next.js (React)

É o "motor" que monta as páginas do site. Deixa a navegação rápida, funciona bem em celular e permite que o Google encontre seu site com mais facilidade nas buscas.

Supabase

É o banco de dados e o sistema de login do site — a mesma ferramenta que você já usa em outros projetos. Guarda os imóveis, os usuários cadastrados, as fotos e os vídeos 3D.

Tailwind CSS

Cuida do visual — cores, espaçamentos e responsividade — de forma organizada, para o site carregar rápido mesmo com um design elaborado.

Supabase Storage

Local seguro onde ficam guardadas as fotos e os vídeos 3D dos imóveis, com controle de quem pode enviar, editar ou apagar cada arquivo.

Sobre os rumores de vazamento

Sua preocupação é legítima — veja como ela é tratada aqui

Vazamentos de senha normalmente não acontecem porque o "Supabase" em si foi invadido — eles acontecem quando um projeto configura mal as permissões do banco de dados (por exemplo, deixando uma tabela aberta para qualquer pessoa ler) ou quando alguém expõe uma chave secreta por engano em código público, como no GitHub. Este projeto é planejado desde o início para evitar exatamente esses dois erros. Abaixo estão as camadas de segurança usadas de fato:

01

Senhas nunca ficam visíveis

O cadastro e o login usam o Supabase Auth, que guarda cada senha como um "hash" (uma versão embaralhada e irreversível). Nem a equipe da imobiliária, nem um eventual invasor, conseguem ler a senha original — só o próprio usuário sabe qual é.

02

Row Level Security (RLS) ativado em todas as tabelas

Cada tabela do banco tem regras que dizem exatamente quem pode ver ou alterar cada linha. Um cliente comum só enxerga os próprios dados; só uma conta marcada como "administrador" pode cadastrar ou editar imóveis. Isso é configurado no banco, não só na tela — mesmo que alguém tente burlar o site, o banco recusa.

03

Chaves e senhas de sistema fora do código

Nenhuma credencial (chave do banco, senha de e-mail, etc.) fica escrita no código do site. Tudo vive em variáveis de ambiente privadas, que não são enviadas ao navegador do visitante nem publicadas em repositórios.

04

Painel de administrador protegido em duas camadas

Além do login, o acesso ao painel /admin verifica se aquele usuário tem a permissão de administrador registrada no banco. Um link descoberto por acaso não é suficiente para entrar.

05

Tudo trafega por HTTPS

A conexão entre o visitante e o site é sempre criptografada, o que impede que dados como senha ou telefone sejan capturados no meio do caminho.

06

Verificação de e-mail e limite de tentativas de login

Novas contas confirmam o e-mail antes de acessar o site, e o Supabase Auth já limita tentativas repetidas de login, dificultando ataques automatizados de adivinhação de senha.

07

Backups automáticos

O banco de dados tem cópias de segurança automáticas, então mesmo em um problema técnico grave nada se perde.

Como o projeto evolui

Da demonstração ao site no ar

1. Protótipo estático (você está aqui)

Validação do design, cores, textos e navegação — sem custos de servidor.

2. Estrutura do banco de dados

Criação das tabelas de imóveis, usuários e fotos/vídeos no Supabase, já com as regras de segurança (RLS) descritas acima.

3. Login e cadastro reais

Integração do formulário de login/cadastro com o Supabase Auth.

4. Painel do administrador

Tela funcional para cadastrar imóveis, enviar fotos e vídeos 3D, e escolher onde cada imóvel aparece na home.

5. Publicação

Site colocado no ar com domínio próprio e certificado HTTPS.
